# ソースコード言語ガイドライン

## 適用シナリオ

1. **新規クラスやメソッドにJSDocを追加する場合**: 英語のJSDocテンプレートを使わず、日本語で記述する。`@example`を書きたくなった場合は、テストコードへの参照に置き換える
2. **エラーメッセージを新規作成する場合**: 開発者が読むログメッセージであっても日本語で記述する。ただしクラス名やメソッド名はそのまま英語で記載する（例: 「MyClass.setup() を呼び出す必要があります」）

## JSDoc

- 日本語で記述すること
- 文体は断定系を使うこと
  - ですます調は使わない
- `@example`は使用しない
  - コード例はコーディング規約との整合性を維持するコストが高い
  - 実装例が必要な場合はテストコードを参照すること

## エラーメッセージ・ユーザー向け文字列

- エラーメッセージは日本語で記述すること
- 例外: 技術的な識別子（クラス名、メソッド名等）は英語のまま記載可

## コメント

- インラインコメントは日本語で記述すること
- 技術用語は英語表記も許容（例: React、useEffect）
- 非自明な設計決定には理由を記載すること
  - 特にアクセシビリティ関連の決定は、準拠する規格・ベストプラクティスを明示する

### アクセシビリティ関連コメント

- 「何をしているか」だけでなく「なぜその設計なのか」を記載する
- 準拠するWAI-ARIAベストプラクティスや規格を明示する
