# ルールJSONインポート機能 E2Eテスト戦略

## 目的

ブラウザ拡張機能としてのJSONインポート機能のエンドツーエンドテストを定義する。
ファイル選択からJSON検証・一括ルール置換・DB永続化までの一連のフローを検証する（プレビュー確認なし）。

## テストスコープ

### 対象フロー

1. ユーザーがルール一覧ページを開く（ルール0件でもインポートボタンが表示される）
2. インポートボタンをクリック → ファイル選択ダイアログ（`<input type="file">`）
3. JSONファイルを選択 → バリデーション → 全既存ルール削除 → JSONルールで置換
4. 成功トースト + ルール一覧リフレッシュ

### 対象ページ

| ページ | URL | 役割 |
|-------|-----|------|
| ルール一覧 | `chrome-extension://{id}/rules.html` | インポート操作 |

### 検証ポイント

| 観点 | 説明 | 例 |
|------|------|-----|
| UI状態変化 | 0件でもインポートボタン表示 | EmptyState表示中でもボタンが見える |
| インポート実行 | 成功トースト + ルール反映 | 「インポートしました」トースト表示 |
| DB永続化 | リロード後もルールが維持される | reloadAndWaitForTable で確認 |
| コンソールエラーなし | クリティカルエラーの不在 | assertNoConsoleErrors で確認 |

## テスト分類

### 1. 正常操作フロー（00-overview.md の受け入れ基準に対応）

インポートボタンクリック → ファイル選択 → インポート実行 → ルール反映

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| 基本インポートフロー | ファイル選択→即実行→ルール反映 | 機能の主要ユーザーストーリーを検証 |
| 0件状態でのボタン表示 | ルール0件でもインポートボタンが有効 | 機能要件「ルール0件でも表示」の確認 |
| 成功トースト | インポート完了後にトーストが表示 | フィードバックUXの確認 |
| DB永続化 | リロード後もインポートルールが存在する | データが確実に保存されることを確認 |

**対応テスト**: `normal-flow.spec.ts`

### 2. バリデーションエラーフロー

不正なJSONファイルや未対応バージョンを選択した場合

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| JSON構文エラー | 不正JSONでエラートースト表示 | L1バリデーションの動作確認 |
| スキーマ不正 | version/rulesなしJSONでエラー表示 | L2バリデーションの動作確認 |
| バージョン不一致 | version:"2.0"でエラー表示 | L3バリデーションの動作確認 |
| ルール0件 | rules:[]でエラー表示 | L5バリデーションの動作確認 |

**対応テスト**: 今後実装予定（`validation-error.spec.ts`）


## テストデータ方針

- `exportedAt` フィールドは `new Date().toISOString()` で動的に生成する（ハードコーディング禁止）
- テスト実行前に `clearAllRules` で既存データをクリーンアップする
- インポートするルールIDは任意の値を使用（DB側で採番される場合も考慮）
