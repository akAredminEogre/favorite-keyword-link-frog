# ルール削除機能 E2Eテスト戦略

## 目的

ブラウザ拡張機能としての削除機能のエンドツーエンドテストを定義する。
ユーザー操作からDB永続化までの一連のフローを検証する。

## テストスコープ

### 対象フロー

1. ユーザーがルール一覧ページを開く
2. 削除したいルールのゴミ箱アイコンをクリック
3. 確認ダイアログが表示される
4. 「削除」または「キャンセル」を選択
5. 削除の場合：ルールが一覧から消え、該当タブがリロードされる
6. ページをリロードしても削除状態が維持される

### 対象ページ

| ページ | URL | 役割 |
|-------|-----|------|
| ルール一覧 | `chrome-extension://{id}/rules.html` | 削除操作 |
| テストページ | `http://localhost:8080/test.html` | DOM置換検証（削除後の動作確認） |

### 検証ポイント

| 観点 | 説明 | 例 |
|------|------|-----|
| UI状態変化 | 削除後のUI表示 | ルール行が消える |
| ダイアログ表示 | 確認ダイアログ | 「本当に削除しますか？」 |
| DB永続化 | リロード後も削除状態維持 | ページリロードで確認 |
| エラー通知 | 失敗時のトースト表示 | 「削除に失敗しました」 |

## テスト分類

### 1. 正常操作フロー

ゴミ箱クリック → 確認ダイアログ → 削除 → 一覧から消える

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| 基本削除フロー | ゴミ箱クリック→確認→削除→行が消える | ユーザー視点での基本操作を確認 |
| ダイアログ表示 | ゴミ箱クリック時に確認ダイアログが表示される | UI遷移が正しいことを確認 |
| 削除ボタン動作 | 確認ダイアログで「削除」クリック後にルールが削除される | 削除実行の確認 |

**対応テスト**: `normal-flow.spec.ts`

### 2. キャンセル操作

確認ダイアログでキャンセル → 何も起こらない

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| キャンセル動作 | 確認ダイアログで「キャンセル」クリック後、ルールが残る | キャンセル操作が正しく動作することを確認 |
| 再クリック可能性 | キャンセル後も削除ボタンを再度クリックできる | 状態がリセットされることを確認 |
| Escapeキー操作 | Escapeキーでダイアログを閉じるとルールが残る | キーボード操作でのキャンセルを確認（ADR-007準拠） |
| オーバーレイクリック | オーバーレイクリックでダイアログを閉じるとルールが残る | マウス操作でのキャンセルを確認（ADR-007準拠） |

**対応テスト**: `cancel-operation.spec.ts`, `dismiss-dialog.spec.ts`

### 2.1. アクセシビリティ

WAI-ARIA Dialog Modal Pattern（ADR-007）に準拠したアクセシビリティ機能

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| フォーカストラップ(Tab) | Tabキーでフォーカスがダイアログ内でループする | アクセシビリティ要件（ADR-007準拠） |
| フォーカストラップ(Shift+Tab) | Shift+Tabキーでフォーカスが逆方向にループする | アクセシビリティ要件（ADR-007準拠） |
| 背景スクロール無効化 | ダイアログ表示中は背景スクロールが無効化される | アクセシビリティ要件（ADR-007準拠） |

**対応テスト**: 
- フォーカストラップ: `focus-trap.spec.ts`（配列ベーステストで実装）
- 背景スクロール: `accessibility.spec.ts`

### 3. DB永続化

ページリロード後もルールが削除されている

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| 永続化確認 | 削除後にページリロード→ルールが一覧に存在しない | 削除がDBに永続化されていることを確認 |

**対応テスト**: `persistence.spec.ts`

### 4. 複数ルール独立性

1つ削除しても他ルールに影響なし

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| 独立性・件数確認 | 1つのルールを削除しても他のルールは残り、件数表示も正しく更新される | 削除が他ルールに影響しないこと、正しい件数表示を確認 |
| 連続削除 | 複数ルールを連続して削除できる | 連続操作の正常動作を確認 |

**対応テスト**: `independence.spec.ts`

### 5. エラー表示

削除失敗時のトースト通知

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| エラートースト | 削除失敗時にエラーメッセージがトースト表示される | ユーザーへのエラー通知を確認 |
| トースト自動消去 | トースト通知が一定時間後に自動で消える | UI/UXが正しいことを確認 |

**対応テスト**: (E2E検証困難、結合テストでカバー)

> **Note**: E2Eテストでエラーを発生させるにはAPIモックが必要だが、E2Eでは実際の環境を使用するため技術的に困難。結合テストでカバーする。

### 6. 重複削除防止・非同期処理

削除処理中の重複防止とUI非ブロッキング

| 分類 | テストケース | 根拠 |
|------|-------------|------|
| 重複ダイアログ防止 | 削除ボタンを素早く連続クリックしてもダイアログは1つだけ表示される | 重複削除を防止（AC-8） |
| UI非ブロッキング | 削除確認ダイアログ表示中も他のルールの編集ボタンはdisabledにならない | 非同期処理でUIがブロックされないことを確認（AC-11） |

**対応テスト**: `concurrency.spec.ts`

## ユーザーストーリートレーサビリティ

| 受け入れ条件（acceptance-criteria.md） | テストケース | テストファイル |
|---------------------------------------|-------------|---------------|
| AC-1: ゴミ箱アイコン表示 | 各行にゴミ箱アイコンが表示される | normal-flow.spec.ts |
| AC-2: 確認ダイアログ表示 | ゴミ箱クリック時にダイアログ表示 | normal-flow.spec.ts |
| AC-3: 削除実行 | 「削除」選択でルール削除 | normal-flow.spec.ts |
| AC-4: キャンセル動作 | 「キャンセル」で何も起こらない | cancel-operation.spec.ts |
| AC-5: 一覧から削除 | 削除されたルールが一覧から消える | normal-flow.spec.ts |
| AC-6: エラー通知 | 失敗時にトースト表示 | E2E対象外（結合テストでカバー） |
| AC-7: タブリロード | 該当タブがリロードされる | E2E対象外（結合テストでカバー） |
| AC-8: 重複削除防止 | 確認ダイアログ表示中の再クリックでもダイアログは1つのまま | concurrency.spec.ts |
| AC-9: 部分的成功 | 削除成功+リロード失敗時の動作 | E2E対象外（結合テストでカバー） |
| AC-10: 物理削除 | DBから物理削除 | persistence.spec.ts |
| AC-11: 非同期処理 | 操作がブロックされない | concurrency.spec.ts |

### E2E検証困難な項目の理由

| 受け入れ条件 | E2E検証が困難な理由 |
|-------------|-------------------|
| AC-6: エラー通知 | 削除エラーを発生させるにはAPIモックが必要だが、E2Eでは実際の環境を使用するため技術的に困難 |
| AC-7: タブリロード | 拡張機能によるクロスタブのリロード制御（chrome.tabs.reload）をE2Eで検証するには、タブIDのマッピングやタイミング制御の複雑さがある |
| AC-9: 部分的成功 | 「削除成功＋タブリロード失敗」の状態を作り出すにはAPIの部分モックが必要だが、E2Eでは困難 |

## テストファイル構成

```plaintext
tests/e2e/pages/rule-list/features/delete-rule/
├── helpers.ts                 # 共有ヘルパー関数（再エクスポート）
├── constants.ts               # 削除機能固有の定数
├── dialog-operations.ts       # ダイアログ操作ヘルパー
├── rule-operations.ts         # ルールテーブル操作ヘルパー
├── normal-flow.spec.ts        # 正常操作フロー
├── cancel-operation.spec.ts   # キャンセル操作（キャンセルボタン）
├── dismiss-dialog.spec.ts     # ダイアログ閉じ操作（Escapeキー・オーバーレイクリック）
├── focus-trap.spec.ts         # フォーカストラップ（配列ベーステスト）
├── accessibility.spec.ts      # アクセシビリティ（背景スクロール無効化）
├── persistence.spec.ts        # DB永続化
├── independence.spec.ts       # 複数ルール独立性
└── concurrency.spec.ts        # 重複削除防止・非同期処理
```

> **Note**: エラー通知（error-notification.spec.ts）はE2E検証困難のため、結合テストでカバーする。

## テスト環境

### 前提条件

- Chrome拡張機能がインストール済み
- テスト用のルールがDBに存在する

### テストデータ

```typescript
// テスト用ルールの例
const testRules = [
  { id: 1, oldString: 'test1', newString: 'replaced1', urlPattern: 'https://example.com/*' },
  { id: 2, oldString: 'test2', newString: 'replaced2', urlPattern: 'https://example.org/*' },
];
```

### Playwrightセットアップ

- Chrome拡張機能のロード
- IndexedDBの初期化とテストデータ投入
- 各テスト前後のクリーンアップ
